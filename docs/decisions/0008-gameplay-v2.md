# ADR 0008：遊戲玩法 v2（審查、4～10 人、匿名投票、斷線作廢）

- 狀態：Proposed（待 team leader 核准）
- 日期：2026-11-26
- 提案：Core A（鄒聿銘）、Core B（張瀚元）
- 討論：#11、#8；相關 PR：#5
- 依賴：ADR 0007（in-process referee：開房者程式內的權威伺服器，所有人參賽，PR #5）。**本 ADR 須在 #5 合併後合併。**
- 關係：**部分取代 ADR 0005**（機密資訊），取代範圍見下方「機密資訊規則」一節；ADR 0005 其餘內容維持有效。

## 背景

原本的 `docs/game-rules.md` 只有基本流程，計分、平票、人數、斷線都標為待定。
Core A/B 在 #11 討論後，整理出完整玩法與 Core 設計（`src/pretend2paint/core/DESIGN.md` v5.1），需要正式核准後才能實作與合併相關測試。

另外有兩個實際問題要解決：

1. 玩家可能在畫裡直接寫字（例如寫出答案），讓間諜照抄，遊戲失去意義。
2. 雖然房主程式內有權威裁判（ADR 0007）負責判定，但斷線、平票、棄票、作廢的結果若沒有明確規則，裁判程式就無法一致地處理，玩家也無法預期結果。

## 決策

完整條文見 `docs/game-rules.md` v2，重點如下：

1. **人數** 4～10 人，全部參賽（開房者也參賽，ADR 0007）。
2. **選間諜** 每局 1 人，加權隨機：權重 1/(1+s)²，s＝已完成回合中當過間諜的次數。
3. **參考圖** 由伺服器自動隨機抽一張一般玩家的畫給間諜（取代間諜盲選）。
4. **新增 REVIEW 階段**：所有畫以隨機順序、每張 5 秒播放給一般玩家，可檢舉「可辨認文字」；每人額度 ⌈(N−3)/2⌉，門檻 ⌈2(N−1)/3⌉；違規作者 −15、第 2 次移出；連續檢舉失敗 −3、−6 並暫停一次審查權。
5. **參考圖違規** → 本局作廢（VOID_REFERENCE），勝負分 0、處罰照算、不算完成回合。
6. **投票**：只有一般玩家能投，匿名投畫作編號；不能投自己、不能投清白畫；可棄票；看不到即時票數。
7. **投票結果**：間諜唯一最高 → 猜詞；一般玩家唯一最高 → 間諜逃脫；全部棄票 → 間諜逃脫；平票 → 猜詞。
8. **計分**（暫定，試玩後可調）：base＝5＋3(N−4)；間諜逃脫 +3、被抓猜對 +1、被抓猜錯 −3、平票猜對 +1、平票猜錯 0；投中間諜的一般玩家得 base（間諜被抓且猜錯時 base＋3）。
9. **斷線**：以結算提交為分界。提交前斷線 → 本局作廢（VOID_DISCONNECT），完全不計分、不算完成回合；提交後斷線 → 結果照算，下一局前移除；剩不到 4 人 → 遊戲結束；不支援重連。
   - **開房者斷線** → 遊戲結束。玩家端顯示**最後一次收到的計分板快照**與其回合編號（「截至第 N 回合」）；若開房者在提交後、廣播前當機，最新一局的結果無法取得，以快照為準；若從未收到任何計分板，顯示「遊戲中斷，尚無分數」。偵測延遲＝p2p 心跳逾時時間。
   - **提交的原子性**：伺服器在單一執行緒依事件抵達順序處理，同一局只能提交一次。VOID_REFERENCE、VOID_DISCONNECT 與正常結算互相競爭時，**先被處理的事件決定結果**，後到的事件不再改變該局。
10. **回合**：完成 5 回合結束（作廢局不算）；各階段秒數可由開房者調整。
11. **排名**：同分同名次；被移出、離開者不列入排名。

### 機密資訊規則（部分取代 ADR 0005）

分成三類：

**(A) 一局結果確定前，只能單播給本人（維持 ADR 0005）**

- 答案、提示、角色：只單播給本人。
- 作者對應（畫作編號 ↔ 玩家）、別人的角色、別人的選票、檢舉票：只存在伺服器，任何玩家都收不到。

**(B) 一局結果確定前，畫作的限定接收者例外（取代 ADR 0005「REVEAL 前畫作只給房主」）**

| 封包 | 接收者 | 內容 |
| :--- | :--- | :--- |
| `CANVAS_SNAPSHOT` | 伺服器 | 作者自己的畫 |
| `SPY_REFERENCE` | 只有間諜 | 1 張參考圖，不含作者 |
| `REVIEW_ITEM` | 逐一單播給每位一般玩家 | 1 張畫＋匿名編號，不含作者 |
| `GALLERY` | 逐一單播給每位一般玩家 | 全部畫＋匿名編號＋清白標記，不含作者 |
| `SPY_GALLERY` | 只有間諜 | 未違規的畫＋匿名編號，不含作者 |

這些封包都不可廣播、不可附帶作者或角色。

**(C) 一局結果確定後的公開例外（新增）**

- 伺服器完成結算提交後，才可**廣播** `REVEAL_ALL`：答案、提示、間諜、每張畫的作者、違規標記、各畫得票數。
- 作廢局（VOID_REFERENCE、VOID_DISCONNECT）提交後同樣公開。
- 提交前任何時候都不得廣播上述內容。

## 影響

- `common/types.py`：`Phase` 需加入 `REVIEW`，順序改為 LOBBY、DEAL、DRAWING、SPY_ACTION、REVIEW、VOTING、SPY_GUESS、REVEAL、ROUND_END（另開 PR）。
- Streaming：新增 `REVIEW_ITEM`、`REVIEW_FLAG`、`START_GAME`、`UPDATE_CONFIG` 等封包，所有遊戲中封包帶 `match_id`、`attempt_id`（見 DESIGN.md 第 7 節）。
- UI：新增審查畫面（逐張 5 秒、檢舉鍵）與各種等待畫面。
- Core：依 DESIGN.md v5.1 實作；核准前，涉及上述規則數值的測試不合併。

## 考慮過的其他做法

| 做法 | 不採用的原因 |
| :--- | :--- |
| 不做審查，只在畫面提示「禁止寫字」 | 無法防止寫答案作弊，遊戲性下降 |
| 開房者只當裁判不參賽 | 少一位玩家；4 人時只剩 3 人能玩 |
| 斷線時回滾已結算資料 | 實作複雜；以提交點切割即可避免 |
| 平票算間諜逃脫 | 間諜太容易獲勝；改為平票要猜詞 |

## 待確認

- 「可辨認文字」的範例（數字、單一字母、符號、箭頭）。
- 計分平衡：10 人時投中間諜可得 23 分，間諜最多 +3。
